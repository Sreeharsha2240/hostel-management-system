# HMS-19 owner coverage-boundary decision — 13 November 2026

**Decision by Sreeharsha, project owner:** For SRS §6.4's “application logic” coverage requirement, use the frozen isolated method selection's **function-body statement diagnostic**. Application logic for this measurement is executable statements inside callable function and method bodies. Imports, class/module declarations, field declarations, choices, and database schema constraints are outside this metric because method-context coverage cannot attribute their execution to an individual unit test. Their associated behavior remains subject to focused tests and review, while the all-application-statements diagnostic remains published as a conservative companion result.

This is an explicit project-owner interpretation of the measurement boundary, not a change to `.coveragerc`, configured CI threshold, historical denominator, or evidence. The function-body boundary and extraction rule are defined and source-pinned in [the reproducible measurement](hms19-all-statements-20261113/measurement-expanded.json) and the [unit review harness](hms19-unit-review-20261113/reproduce.py).

For the frozen expanded selection on source `ee52be71c808abbebceb3d135a4e9fa76f9ec53d`, **288/288 isolated tests passed with zero database attempts**. The accepted function-body statement result is **946/946 = 100.00%**, above the 70% requirement. The companion all-application-statements result is **946/1,703 = 55.55%**; the separate branch diagnostic is **378/426 = 88.73%**. Existing exact-source two-version CI evidence is linked in the report. This decision does not claim that all application statements or every declarative rule received coverage credit.

The owner provided this approval in the project conversation on 13 November 2026 and requested that the report adopt this boundary. It records project scope approval only; it does not fabricate a separate teammate QA review or instructor sign-off.
